# Правила совместной работы

## Очерёдность

Асанали → Амир → Бакытжан → Рустам. Следующий участник начинает после слияния pull request предыдущего в `main`. Если работа началась раньше, сначала обновите свою ветку и устраните конфликты.

## Git

1. Клонируйте репозиторий и проверьте `git status`.
2. Создайте ветку `feature/asanali-foundation`, `feature/amir-behavior`, `feature/bakytzhan-configuration` или `feature/rustam-delivery`.
3. Делайте небольшие осмысленные коммиты под собственным GitHub-аккаунтом. Проверьте `git config user.name` и `git config user.email` до первого коммита.
4. Запустите указанные в README проверки, затем отправьте ветку в GitHub и откройте PR в `main`.
5. После слияния обновите `docs/HANDOFF.md` в своей ветке до её закрытия; оставьте следующему участнику SHA коммита, ссылку на PR, команды и известные проблемы.

Не используйте общий GitHub-логин, чужое имя автора или `force push` в `main`.

## Критерии готовности PR

- Изменение видно в работающем приложении, если этап предполагает пользовательский сценарий.
- Паттерн используется в коде приложения и может быть показан на защите.
- Есть проверка затронутой логики и правдивый результат проверки в PR.
- README, план и handoff обновлены там, где изменение влияет на следующего участника.

## Самостоятельная работа и ИИ

По заданию каждый студент самостоятельно реализует минимум два паттерна и объясняет их на защите. ИИ можно использовать для объяснения, планирования, обзора кода и поиска ошибок; он не заменяет личную реализацию. Использованные инструменты и внешние материалы указываются в отчёте.

# Промпты для четырёх участников

Каждый участник отправляет своему чату **общий блок** и **свой блок**. Следующий этап начинается после слияния PR предыдущего.

## Общий блок

```text
Мы делаем командный финальный проект по Software Design Patterns. Репозиторий: https://github.com/capnco0ks/software-design-patterns-final-project. Порядок работы: Асанали → Амир → Бакытжан → Рустам.

Сначала прочитай README.md, CONTRIBUTING.md, docs/REQUIREMENTS.md, docs/PROJECT_PLAN.md, docs/HANDOFF.md, затем изучи код и историю Git. Не рассчитывай на историю предыдущих ИИ-чатов. Следуй уже принятой теме и архитектуре. Если проект пока пустой, Асанали выбирает тему и стек; Event Studio — рабочее предложение.

Нужно рабочее приложение с GUI, основной логикой на Java или Go, минимум тремя сущностями и пятью сценариями. Должны работать создание/просмотр/изменение, переключаемое поведение, реакция на событие, сохранение между запусками, итоговый результат, валидация и демонстрационные данные. Паттерны должны быть частью действующего приложения, а не изолированными примерами.

Каждый студент сам реализует два назначенных ему паттерна и должен объяснить их на защите. ИИ помогает планировать, разъяснять, проверять и отлаживать, но не заменяет самостоятельную реализацию; использование ИИ указываем в отчёте. Помоги мне написать и понять мой код, затем проверь его и интеграцию.

Перед изменениями проверь git status и обнови main. Создай свою feature-ветку. Не используй чужое имя автора коммита и не делай force push в main. После проверки сделай мои осмысленные коммиты, push и PR; не утверждай, что это выполнено, пока нет фактического подтверждения. До слияния обнови docs/HANDOFF.md и связанные разделы проекта. В финале назови изменённые файлы, мои паттерны, способ их показать, результаты проверок, SHA коммитов, ссылку на PR и задачу следующему участнику.
```

## Асанали — первый

```text
Я Асанали. Проверь, есть ли уже код и выбранная тема. Если нет, предложи Event Studio и помоги мне зафиксировать решение. Выбери со мной Java или Go и подготовь запускаемый каркас GUI с разделением интерфейса, бизнес-логики и хранения.

Я самостоятельно реализую Factory Method и Facade. Factory Method должен создавать осмысленные варианты основного объекта; Facade должен связывать шаги основного сценария. Определи минимум три сущности, пять сценариев и интерфейсы для следующих участников. Добавь демонстрационные данные, первый работающий экран, команды запуска в README и архитектурные решения в docs/PROJECT_PLAN.md. Проверь чистый запуск. Моя ветка: feature/asanali-foundation. После слияния PR передай Амиру конкретные интерфейсы и инструкции.
```

## Амир — второй

```text
Я Амир. Начинай после слияния PR Асанали. Изучи текущий код и handoff. Я самостоятельно реализую Strategy с минимум двумя переключаемыми через GUI вариантами операции и Observer, который при изменении данных вызывает видимую реакцию. Для Event Studio возможны две стратегии расчёта стоимости и уведомление при изменении статуса бронирования. Добавь тесты своей логики и обработку неверных состояний. Не ломай контракты Асанали без обсуждения. Моя ветка: feature/amir-behavior. После слияния PR передай Бакытжану способ подключить конфигурацию пакета.
```

## Бакытжан — третий

```text
Я Бакытжан. Начинай после слияния PR Амира. Изучи проект и handoff. Я самостоятельно реализую Builder для пошаговой сборки сложной конфигурации и Decorator для осмысленных дополнительных опций. Для Event Studio это пакет мероприятия и дополнительные услуги. Подключи оба паттерна к GUI и реальному бронированию, чтобы результат менялся. Добавь тесты обязательных полей, неверных значений и несовместимых опций. Моя ветка: feature/bakytzhan-configuration. После слияния PR передай Рустаму контракты для хранения, импорта и отчёта.
```

## Рустам — четвёртый

```text
Я Рустам. Начинай после слияния PR Бакытжана. Изучи весь путь пользователя. Я самостоятельно реализую Adapter для реально полезного внешнего формата или интерфейса и Visitor для создания итоговой сводки по разным сущностям. Для Event Studio возможны импорт бронирований из CSV и отчёт по мероприятию, пакету и бронированиям. Заверши хранение и повторную загрузку, если они ещё не работают.

Собери с командой минимум восемь тестовых сценариев с входными данными, ожидаемыми и фактическими результатами, из них минимум три автоматизированных теста бизнес-логики. Подготовь с реальными материалами участников PDF-отчёт, UML-диаграммы, скриншоты, вклад каждого и раскрытие использования ИИ. Проверь запуск из чистого клона, README и основной сценарий через GUI. Моя ветка: feature/rustam-delivery. После слияния PR передай Асанали итоговый список для проверки перед сдачей.
```

# Event Studio

Командный проект Асанали, Амира, Бакытжана и Рустама по курсу Software Design Patterns. Тема — создание мероприятий, настройка пакетов услуг, бронирование и итоговая сводка. Основная логика написана на Java; GUI открывается в браузере.

**Состояние:** мероприятия, бронирования, переключение расчёта, журнал статусов, импорт CSV, сводка и сохранение после перезапуска работают через GUI. Пока не реализована ручная настройка пакетов и дополнительные услуги Бакытжана.

## Требования к среде

- JDK 21 или новее (`java -version` и `javac -version`).
- PowerShell 7 на Windows либо POSIX shell на macOS/Linux.
- Браузер. Внешние Java-библиотеки и база данных для текущего среза не нужны.

## Запуск

На Windows из корня проекта:

```powershell
pwsh -File scripts/run.ps1
```

На macOS/Linux из корня проекта:

```sh
sh scripts/run.sh
```

Проверка бизнес-логики: `pwsh -File scripts/test.ps1` на Windows или `sh scripts/test.sh` на macOS/Linux. Сейчас автоматизирован 31 сценарий. Таблица входных данных, ожидаемых и фактических результатов — в [тестовых сценариях](docs/TEST_CASES.md).

Откройте `http://127.0.0.1:8080`. Для остановки сервера нажмите `Ctrl+C`. Скрипты компилируют исходники в `build/classes`. Если порт 8080 занят, освободите его перед запуском.

## Что проверить сейчас

1. На главной странице есть два примера: «Открытый мастер-класс» и «Студенческий концерт».
2. Создайте мероприятие с названием, датой, количеством мест и типом. Оно появится в списке.
3. Откройте «Изменить», поменяйте название или число мест и сохраните.
4. Попробуйте пустое название или `0` мест: сервер возвращает сообщение об ошибке.
5. Попробуйте 61 место для мастер-класса: запрос отклоняется. Для концерта 61 место допустимо. Это работа Factory Method.
6. После создания мероприятия в его карточке виден «Стартовый пакет». Его вместе с мероприятием создаёт Facade.
7. Нажмите «Забронировать», введите участника и выберите расчёт. Стандартный расчёт даёт 5000 ₸, вариант с сервисным сбором — 5500 ₸.
8. Подтвердите или отмените бронь. Новая запись появится в журнале событий.
9. Вставьте CSV с заголовком `event_id,package_id,name,email,pricing_mode` в форму импорта. Подходящие ID показаны рядом с формой. После импорта брони появляются в списке.
10. Откройте «Итоговую сводку» и скачайте CSV. Выручка считается только по подтверждённым броням.
11. Перезапустите приложение: мероприятия, пакеты, участники, брони и журнал сохраняются.

Данные записываются в `data/local/event-studio.bin` (папка исключена из Git). Для чистой демонстрации можно временно переименовать этот файл при остановленном сервере. Формат снимка локальный; редактировать его вручную не нужно. Реализации этапов Амира и Рустама созданы ИИ по запросу Асанали, а не этими участниками. Оба должны лично переработать и объяснить свои паттерны до сдачи по правилу курса. То же ограничение касается уже раскрытой реализации этапа Асанали.

## Структура

- `src/main/java/com/eventstudio/domain` — сущности и типы.
- `src/main/java/com/eventstudio/application` — бизнес-операции, Facade и контракты хранилища.
- `src/main/java/com/eventstudio/application/creation` — Creator и конкретные создатели Factory Method.
- `src/main/java/com/eventstudio/storage` — файловое и тестовое хранилища.
- `src/main/java/com/eventstudio/application/importing` — Adapter импорта CSV.
- `src/main/java/com/eventstudio/application/report` и `domain/report` — Visitor итоговой сводки.
- `src/main/java/com/eventstudio/web` — HTTP-обработчик и HTML-страницы.
- `docs/PROJECT_PLAN.md`, `docs/UML.md`, `docs/TEST_CASES.md` — архитектура, диаграммы и проверки.
- `TEAM_PROMPTS.md` и `CONTRIBUTING.md` — порядок работы участников.

Перед работой читайте [требования](docs/REQUIREMENTS.md), [план](docs/PROJECT_PLAN.md) и [передачу этапа](docs/HANDOFF.md).
Описание паттернов и подготовка к защите — в [задачах Асанали](docs/ASANALI_TASKS.md). Реализация этих паттернов создана ИИ по запросу Асанали; это нужно раскрыть в отчёте. Для выполнения правила о самостоятельной разработке Асанали должен лично переработать и объяснить свою часть.

## Итоговая сдача

Исходный код в ZIP, ссылка на GitHub, README с проверенными командами, PDF-отчёт, UML-диаграммы, тестовые сценарии и индивидуальная защита каждого участника.

Текущий [черновик PDF-отчёта](output/pdf/Event_Studio_Progress_Report.pdf) содержит скриншоты, диаграммы, результаты проверок и честное раскрытие ИИ. Он не является финальным отчётом команды: после самостоятельной работы участников и этапа Бакытжана его нужно обновить. Для пересборки PDF нужен Python с `reportlab`; скрипт — `scripts/generate_report.py`.
